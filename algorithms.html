CS 499 Enhancement Two

Algorithms and Data Structures

An algorithmic enhancement of the Grazioso Salvare Rescue Match Recommendation System using efficient data structures, candidate selection, weighted scoring, and top-k ranking.

Original Course: CS 340 Python Dictionary Indexes Set Operations Binary Search Bounded Min-Heap

Artifact Overview

The artifact selected for the algorithms and data structures category is the Grazioso Salvare animal rescue dashboard originally developed in CS 340: Client/Server Development. The application uses Python, Dash, Pandas, MongoDB, PyMongo, Plotly, and Dash Leaflet to help users identify animals that may be suitable for specific rescue-training roles.

The original dashboard allowed users to select Water Rescue, Mountain or Wilderness Rescue, or Disaster or Individual Tracking and then displayed matching records in a table, breed visualization, and interactive map.

Although the original application successfully filtered shelter records, its rescue-selection process relied primarily on predefined database queries and repeated filtering conditions. Animals were generally treated as either matching or not matching a rescue profile.

Original and Enhanced Algorithm Design

Enhancement Two moved the application beyond repeated filtering and introduced data structures and algorithms specifically selected for candidate lookup, intersection, age-range searches, scoring, ranking, and repeated recommendation requests.

Area Original Artifact Enhancement Two
Candidate Lookup Records were repeatedly filtered through predefined conditions. Dictionary-based indexes provide efficient access to candidate groups organized by normalized characteristics.
Multi-Criteria Filtering Similar filtering operations were repeated against the dataset. Set intersections efficiently combine breed, sex, outcome, and other candidate groups.
Age Search Records could be examined through repeated filtering for age requirements. Sorted age information and binary search identify qualifying range boundaries.
Candidate Evaluation Animals were primarily treated as matching or not matching a rescue profile. Weighted scoring evaluates how closely each candidate matches the selected rescue requirements.
Ranking The original application did not maintain a specialized top-k ranking structure. A bounded min-heap maintains the strongest candidates while records are evaluated.
Repeated Requests Similar recommendation calculations could be repeated for identical requests. Bounded caching allows recently calculated recommendation results to be reused.

Key Algorithm and Data Structure Improvements

Dictionary-Based Indexes

Dictionaries organize records by frequently used characteristics such as normalized breed, sex, and outcome, supporting efficient key-based candidate retrieval.

Set Intersections

Sets allow multiple candidate groups to be intersected efficiently instead of repeatedly scanning the complete collection for every criterion.

Binary Search

Sorted age information allows binary search to identify the boundaries of qualifying age ranges more efficiently than repeated sequential filtering.

Weighted Scoring

Candidates receive explainable suitability scores based on breed, age, sex, and outcome criteria, allowing stronger matches to be distinguished from weaker ones.

Bounded Min-Heap

A bounded priority queue maintains only the strongest requested candidates instead of requiring every candidate to be completely sorted when only the top results are needed.

Bounded Caching

Recently calculated recommendation requests can reuse cached results while bounded cache sizes prevent uncontrolled memory growth.

Weighted Recommendation Model

The recommendation engine evaluates each candidate using a 100-point suitability model. The weights reflect the relative importance of the characteristics used for the selected rescue profile.

40 Breed Match
25 Age Match
20 Sex Match
15 Outcome Match

The scoring process also provides explanatory match reasons. This allows users to understand why a candidate received a particular ranking rather than presenting the recommendation as an unexplained result.

Algorithmic Efficiency

I evaluated the enhancement not only by whether it produced correct results, but also by how the selected structures affected lookup, search, and top-candidate selection.

Dictionary Lookup

O(1)

Expected average-case access to candidate sets associated with indexed values.

Binary Search

O(log n)

Locates the boundaries of qualifying age ranges in sorted age data.

Top-k Selection

O(m log k)

Maintains a limited number of strongest recommendations instead of fully sorting all candidates.

A full candidate sort requires approximately O(m log m), where m represents the number of evaluated candidates. The bounded min-heap reduces top-k selection to approximately O(m log k), where k represents the number of requested recommendations.

Because the dashboard normally displays only the strongest ten candidates, this approach provides a useful trade-off between performance, readability, and implementation complexity.

Reflection Narrative

Enhancing this artifact strengthened my understanding of the relationship between data organization and algorithm performance. The original dashboard successfully filtered animal records, but the selection logic relied primarily on predefined queries and repeated filtering conditions. Enhancement Two required me to consider whether different data structures could provide a more efficient and useful recommendation process.

One of the most important lessons I learned was that no single data structure is automatically the best choice for every operation. Dictionaries provide efficient key-based access, while sets are useful for membership testing and intersections. Sorted data supports binary search, and a bounded min-heap is useful when only a limited number of top-ranked results are required.

The enhancement also required me to evaluate the trade-offs associated with these structures. Dictionary indexes and caches improve lookup and response time but require additional memory. Sorted age information supports efficient range searches but must remain consistent as records change. A heap provides an efficient top-k solution, while a complete sort may still be appropriate when every candidate must be displayed in ranked order.

The weighted scoring model changed the application from a strict filtering system into a recommendation-oriented decision-support tool. Instead of treating every matching animal equally, the enhanced system evaluates breed, age, sex, and outcome characteristics and assigns an explainable suitability score. This allows users to distinguish between acceptable candidates and the strongest candidates.

Testing was especially important because the algorithmic enhancement needed to improve candidate selection without breaking the existing application. Automated tests allowed me to evaluate indexing, intersections, binary search, scoring, heap behavior, caching, validation, and integration independently. End-to-end testing then confirmed that the table, chart, map, and recommendation components continued to work together correctly.

This enhancement most directly supports the computer science outcome involving the design and evaluation of computing solutions using algorithmic principles. It also demonstrates the use of well-founded computing techniques to deliver practical value and communicate technical results to both technical and nontechnical audiences.

Overall, Enhancement Two transformed the artifact from a filtering dashboard into a recommendation system capable of organizing data efficiently, narrowing candidate groups, evaluating suitability, and prioritizing the strongest results. The enhancement strengthened my ability to select algorithms based on actual application requirements while balancing performance, memory use, readability, maintainability, and user needs.
